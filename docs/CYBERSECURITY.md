# Cybersecurity Learning Track

## Direction

Prioritise **defensive cybersecurity, medical-device safety and privacy, SOC fundamentals, and cloud security**. Use general cybersecurity practice as a foundation for the longer-term goal of working around connected medical devices and hearing technology.

## Learning sequence

### Stage 1 — Core foundations
- [ ] Networking: TCP/IP, DNS, HTTP/S, ports, routing, and TLS basics
- [ ] Linux and Windows fundamentals
- [ ] Command line and scripting basics
- [ ] Identity, authentication, authorisation, and least privilege
- [ ] Logs, alerts, and basic incident terminology

### Stage 2 — Defensive operations
- [ ] Learn SIEM concepts and basic log queries
- [ ] Practise alert triage with safe, authorised labs
- [ ] Write short incident timelines and evidence-based reports
- [ ] Learn vulnerability management and patch prioritisation
- [ ] Study backups, recovery, and basic threat modelling

### Stage 3 — Cloud and product security
- [ ] Cloud identity and access management
- [ ] Secure configuration, audit logging, and key management
- [ ] API security and secrets management
- [ ] Software supply-chain and dependency risk
- [ ] Privacy-by-design and data minimisation

### Stage 4 — Medical-device focus
- [ ] Map assets, trust boundaries, and data flows for a connected hearing-aid ecosystem
- [ ] Study Bluetooth Low Energy security at a conceptual and authorised lab level
- [ ] Review companion-app permissions and update pathways
- [ ] Learn medical-device risk management and security documentation
- [ ] Connect security findings to patient safety, clinical workflow, and privacy
- [ ] Practise evidence-grounded risk reports with explicit limitations

## Portfolio evidence

Prefer small, reviewable artifacts over certificate collecting alone:

- [ ] A sanitised SOC alert-triage report
- [ ] A cloud security checklist with test evidence
- [ ] A threat model for a fictional connected hearing-aid system
- [ ] A privacy and data-flow diagram
- [ ] A documented HearSec assessment with traceable evidence

## Safe practice rules

Only test systems you own or have explicit permission to assess. Use training labs, synthetic data, and fictional device diagrams. Do not publish secrets, private data, or unverified claims about real products.

## Review cadence

Choose one technical topic and one portfolio artifact at a time. Record what was tested, what evidence supports the result, and what remains unknown.
